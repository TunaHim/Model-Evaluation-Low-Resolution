How the evaluation pipeline works

This page covers the data and software side of the multi-model evaluation of the Destination Earth Climate DT Low-Resolution Archive (LRA). It shows how monthly output from three coupled storm-resolving models is gathered from the HPC file system, consolidated into analysis-ready series and compared, on one common grid, with three independent observational references.

3. Problems the pipeline had to solve

data volume

Many files per model

Each model stores its monthly output as many separate NetCDF files per variable. open_mfdataset treats them as one lazy dataset, and the consolidated series is written once, so later steps never touch the raw files again.

grids

Different grids

ERA5 is 0.25° and ESA-CCI has its own grid. Every reference is brought to the model's 1° grid before any difference or statistic is computed.

checks

Check before compare

After regridding, the notebook prints whether latitude and longitude match exactly, counts NaNs and checks units (K vs °C), so a silent mismatch cannot reach a figure.

longitude wrap

No seam at 0°

The xesmf regridder is built with periodic=True, so values near the dateline or Greenwich are not lost or smeared.

reuse

Derived files

Trends, standard deviations and consolidated series are saved as NetCDF in one evaluation folder, so plots can be redrawn without recomputing.

portability

No hard-coded paths

All data locations sit in one config cell as documented placeholders. A conda environment.yml (Python 3.10, xesmf, dask) pins the software.

5. What could come next

IdeaWhy
Shared helper moduleThe load, regrid and check steps repeat across notebooks. Moving them into one tested Python module would remove copies.
Tests and CIThere are no automated tests yet. Small synthetic grids would let the regridding and trend code be checked on every push.
Cloud-native storeWriting the consolidated series as chunked Zarr would let them be read remotely without the HPC file system.
Workflow runnerA small Snakemake or Make file could rebuild all derived files in order when new LRA years arrive.

6. In one sentence

Monthly LRA output from three Climate DT models is read lazily from the HPC file system, consolidated into one series per model and variable, brought onto one common 1° grid with the references and checked, and then turned into trends, variability, Taylor statistics and maps for 1990–2014.
